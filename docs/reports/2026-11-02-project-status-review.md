## 已有业务能力

### 官网 / 商城

- 商品列表和详情按 `ONLINE`、`INQUIRY_ONLY`、`PREORDER` 区分线上购买、咨询和预售展示。
- 有登录注册、个人资料、用户 / 游客订单、购物车、结账和 Stripe 支付页；支付意图复用、过期后重建和订单支付展示有历史 QA 证据。
- 固定预约页读取真实预售商品，一次选择 1 至 2 款产品，提交后展示结果，不直接展示优惠码。
- 预约表单已有牧场名称、羊群数量、品种和可选测试计划报名；本地最新代码还包含按产品展示的 Survey、国家选择、Google 地址搜索和隐藏结构化字段提交。
- 旧项目页写到的“通知中心 / notification store 已完成”缺乏当前前端源码支撑，不计入本次确认的能力。

### 管理后台

- 商品、分类、购买模式、商品上下架，以及预售模式下的表单和库存展示已有实现。
- 在线订单详情、发货 / 物流 / 操作历史、咨询订单处理已有对应页面和接口调用。
- 用户管理是真实 API 功能，包含筛选、角色、启停和删除；旧协调文档的“用户管理未实现”已经过时。
- 预售线索列表 / 详情、优惠码、邮件状态、失败信息和重发操作已有实现。
- 本地最新代码增加产品测试申请的列表 / 详情、状态 / 备注、资格邮件和导出，并增加牧场及 Survey 展示。
- 首页仪表盘仍以模板和占位数据为主：统计请求被注释，图表使用 mock 数据，不能视为真实经营分析功能。

### 后端

- Koa + TypeScript + Prisma + **MySQL**；旧项目说明中的 MongoDB 描述不准确。
- 已有认证和角色、商品 / 分类、购物车、用户 / 游客订单、发货和 Stripe 支付 / Webhook 等接口。
- 预售领取已支持多产品分别生成 lead / 优惠码，邮箱与产品去重，后台查询及邮件重发。
- 当前优惠码业务口径为 **15% 优惠、10 位大写字母数字、永久有效**，`expiresAt=null`；旧计划中的年底过期、邮件产品主图等规则已被后续任务替代。
- 测试计划报名独立存储，支持后台状态、备注、资格邮件及 CSV 导出；结构化地址已进入预约线索和测试申请，CSV 也已有六个地址字段。
- **结账输入优惠码抵扣、核销和使用状态闭环尚未实现**，属于旧计划明确排除的后续范围。
- 预约页仍有结账使用优惠码的说明，早于实际核销能力；正式售卖前需要对齐这段对外文案和功能。
- 旧文档声称完整地址 CRUD 已完成，但当前地址路由主要覆盖列表、自动补全和缓存管理，不能直接承诺完整收货地址管理能力。

### 发布方面的关键缺口

1. **后端默认构建不能作为完整发布依据。** `package.json` 的 `build` 使用 `tsconfig.backend008.json`，其依赖图没有 `src/app.ts` 和 `src/routes/index.ts`；干净检出执行默认 build 不会生成 `start` 所需的 `dist/app.js`。本地已有 `dist` 或部署压缩包会掩盖此问题。
2. **数据库迁移没有完整进入版本管理。** 本机有 6 个迁移目录，Git 只跟踪 3 份 SQL；测试申请建表、牧场扩展字段、Survey 三份迁移被 `.gitignore:131` 忽略。仓库还缺完整建库基线，不能证明新环境可以只靠现有迁移复现。
3. **最新三端预售链路尚缺完整验收记录。** 当前通过的是有限范围的类型检查和 mock 测试；真实邮件、测试资格邮件、Google 地址、后台导出、支付失败恢复仍需隔离环境联调。
4. 预约邮件由进程内异步任务触发，缺少持久任务队列；需验证进程中断后 `PENDING` 邮件的排查和重发流程。
