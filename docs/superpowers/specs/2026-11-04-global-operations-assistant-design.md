# 全局运营助手设计规格

日期：2026-11-04
状态：待用户审阅

## 目标

把管理后台的运营助手从独立页面改为全局悬浮入口和聊天窗口。管理员与运营人员可以在各管理页面间导航时继续使用同一会话，请求不会因路由切换或关闭窗口而被取消。

## 已确认要求

- 仅 `admin` 和 `operator` 可见、可用。
- 移除原“运营助手”菜单项和 `/operations-assistant` 路由，不保留旧 URL 入口。
- 助手窗口挂在后台主布局，覆盖所有使用该布局的管理页面。
- 关闭窗口、窗口隐藏或切换业务页面只改变界面显示，不取消运行中的请求。
- 只有用户显式取消、退出登录、账号切换或权限被撤销时才取消请求并清理内存状态。
- 保留现有账号隔离的本地会话历史：7天、最近10个会话、每会话最近10轮。
- 后端单轮总预算为180秒，前端等待预算为190秒；模型请求最多4次、工具执行最多6次，不自动重试。
- 模型仍为 `gpt-6.1-sol`；不新增数据库表、迁移、MCP 服务或商城改动。

## 方案

在 `BaseLayout` 中挂载一个全局助手组件，使其生命周期由管理应用壳而非当前业务路由控制。组件包含固定在右下角的悬浮按钮和右侧聊天抽屉，使用现有 Naive UI、Pinia 聊天状态、API 服务、结果卡片、引用安全校验及国际化文案。

抽屉在桌面端使用受限宽度并关闭遮罩，避免阻挡侧边栏和页面导航；窄屏时占满可用视口。路由切换期间抽屉与会话保持挂载，输入、历史、加载状态及响应继续有效。关闭抽屉不触发 store 的 `cancel`；抽屉内保留明确的取消按钮。点击安全引用时关闭抽屉，再导航到已验证的业务详情。

现有会话列表改为适合窄窗口的会话选择和新建、删除、清空控制。结果、统计卡片、筛选条件、查询时间、错误提示及中英文行为保持现有合同。

权限与身份继续以现有认证 store 为准。聊天组件根据当前 `userId` 和角色加载能力并初始化会话；退出、切换账号或失去允许角色时关闭窗口、取消请求、清空内存。已保存历史仍按原存储键及账号隔离规则恢复。

后端能力接口的 `timeoutMs` 改为 `180000`。后台聊天 API 超时和 Pinia 的本地截止时间统一为 `190000`，留出接收后端504响应的时间。不得扩大模型/工具次数或增加自动重试。

## 范围

涉及后台根应用布局、助手组件与 store、路由生成源及生成类型、助手 E2E、后端助手时限测试/API 契约、本地使用说明和文档中心任务/验收记录。商城、业务数据库、认证合同、助手工具和既有数据查询均不变。

## 验收

- 管理员和运营账号在后台业务页面看到可访问的悬浮入口；普通用户和登录页不可见。
- 助手在一个管理页面发起延迟请求后切换到另一个管理页面，不能出现 abort、不能重复调用；重新打开窗口后能看到最终响应和引用。
- 关闭窗口不取消请求；显式取消会中止请求且不保存未完成结果。
- 退出登录、账号切换或权限撤销会取消请求、关闭窗口并清空内存；另一账号无法看到前一账号会话。
- 点击有效记录引用会关闭聊天窗口并打开已有详情；不安全引用仍被拒绝。
- 旧菜单、路由类型和 `/operations-assistant` URL 均已移除；悬浮入口正常。
- 会话选择、刷新恢复、删除、清空、中英文、窄屏和失败状态通过回归。
- 能力接口报告 `timeoutMs=180000`；后端超时测试、前端API/状态截止值为190秒，模拟耗时超过原100秒的请求可完成。
- 后端 `npm test`、全量 TypeScript 检查、默认构建通过；后台 E2E、`pnpm typecheck`、`pnpm exec eslint . --no-fix`、`pnpm build:test` 通过，ESLint 不新增 errors 或 warnings。

## 风险与处理

移除旧 URL 后，原收藏链接将进入后台的未匹配路由处理。这是用户明确要求的入口变更。会话继续使用现有存储格式，因此刷新和账号隔离行为保持兼容。全局组件仅随后台主布局挂载；登出会通过现有认证重置逻辑中止请求。
